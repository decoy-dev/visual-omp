# Session handoff, 2026-09-30

This handoff records visual-omp's state after the session that developed the first build (0.1.0) and published the first release (0.2.0).

## What shipped in 0.2.0

visual-omp 0.2.0 was published as a stable GitHub release (tag `v0.2.0` at `20cf769`) with Apple Silicon and Intel disk images and a Windows installer. The release workflow added `Casks/visual-omp.rb` in `3d911f7`. The release notes reproduce the 0.2.0 section of CHANGELOG.md. The release includes these changes:

- **Start chat…** opens a folder chooser with an in-app folder browser and inline folder creation, and an unsent chat can move to another folder.
- **Settings → Providers** uses `omp login` and `omp auth-broker logout` to manage sign-in.
- On macOS, live-follow displays changes to chats that are open in a terminal omp, and **Continue here** uses the best-effort ownership checks the owner accepted. On Windows, saved chats show a notice to close the terminal copy before replying.
- **Settings → About** checks for visual-omp and omp updates and starts the update for the detected install method: Homebrew upgrades in an in-app terminal, other macOS installs download the disk image, and Windows runs the downloaded installer.
- The interface was redesigned around one teal accent with Phosphor icons and motion, the UI copy was rewritten to the voice guide, and the "Prompt" periscope logo (C1, chosen from `docs/logo-concepts/`) replaced the Circuit V.
- Release notes come from CHANGELOG.md, and prereleases no longer update the Homebrew cask.

## Open decisions

- **0.2.0 was broken on macOS, and 0.2.1 fixes it.** electron-builder skipped signing, so the 0.2.0 bundle carries only Electron's linker signature, and macOS reports a quarantined copy (any Homebrew or browser download) as "visual-omp is damaged and can't be opened". `821a12b fix(release): ad-hoc sign the whole macOS bundle` (`mac.identity: "-"`, `hardenedRuntime: false`) fixes it, and the owner chose on 2026-10-01 to publish it as 0.2.1. A local build passed `codesign --verify --deep --strict`, and a quarantined copy opened to the "Not Opened" dialog that leads to **Open Anyway** instead of the damaged error.
- **Not in 0.2.1:** checking GitHub on every launch. The app currently reuses a successful saved update check for up to six hours, including a result that found no update, so relaunching during that period can miss a newly published release. The owner has been offered this change but has not decided.
- **The owner's machine:** `/Applications/visual-omp.app` (0.2.0, installed with `brew tap decoy-dev/tap https://github.com/decoy-dev/visual-omp` and `brew install --cask decoy-dev/tap/visual-omp`) reports the damaged error until it is upgraded to 0.2.1 with `brew update` and `brew upgrade --cask visual-omp`. The interim workaround is `xattr -dr com.apple.quarantine /Applications/visual-omp.app`, which the owner runs themselves. The old local builds in `release/mac-arm64/` and `release/mac/` (0.1.0) have the same signature problem.
- **The GitHub repo description** still contains an em dash. The proposed replacement, not yet applied, is "visual-omp provides a desktop interface for the omp (oh-my-pi) coding agent, with chats, projects, plan review and subagents."

## Known gaps, documented but not fixed

- Four gaps predate this session:
  - The transcript view menu shows a "⌘O" hint, but ⌘O opens a folder.
  - The Windows title bar overlay is 44px tall while the renderer's bar is 40px.
  - Shortcut hints show Mac glyphs on every platform.
  - "Agent working" in `src/renderer/src/ui/Chip.tsx` and the "Context usage" aria-label in `src/renderer/src/ui/ContextRing.tsx` are hard-coded English.
- A newly created folder sorts to the bottom of the sidebar until its first chat is saved.
- Copies of 0.1.0 learn about a release only after their six-hour saved check expires, or when the user clicks **Check for updates** in Settings → About. Their notice also suggests `brew upgrade`, which fails for copies that were not installed with Homebrew.

## Verification

The prior session reported live verification in a development build of the folder chooser (browse, create folder, retarget), live-follow updating as a terminal omp wrote, the Providers tab with omp's login picker, the About update status, dark mode, the new logo, and the restored-chat fix. CI passed on macOS and Windows, and the release workflow published all assets.

The prior session did not report live verification of a Homebrew upgrade, the disk image and Windows installer flows, Windows behavior, VoiceOver, sheet exit animations, the tab overflow menu, or sending a message in a new chat.
