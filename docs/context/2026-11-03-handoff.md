### Fixes and features with CHANGELOG lines (Unreleased)
- `ef5e6f8`: rewinding to one of your messages now hides the later messages right away. The display leaf is omp's bookkeeping entry before the message, which the live stream never carries; `activeBranch()` now bridges a left-out explicit leaf like a missing parent.
- `8ec127d`: shell (`!`) and Python (`$`) runs appear in live and saved chats.
- `f5207f7`: background-job waits end when the last job is cancelled or finishes without another reply, so queued messages continue. The controller samples omp's job and delivery state through the private native bridge while it waits.
- `fa09296`: expanded shell tool cards name omp's output filter and the sizes before and after (omp 18.16 `details.meta.minimized`).
- `e76c68c`: an image omp cannot read is no longer sent as its file path in classic chats. Classic image sends now wait for omp's image token before the text goes in; rejected attachments stay queued with omp's error. Recovery shuts omp down through the SDK instead of typing `/restart` or `/exit` into a contaminated editor.
- `3caf510`: closing a chat on Windows releases node-pty's ConPTY worker and JavaScript pipes (node-pty 1.1.0 keeps them; upstream issues #887 and #947). Any node-pty upgrade must review `windows-pty-cleanup.ts`.
- `7a1a3fc`: Settings > Providers offers Sign out for stored API keys from providers without usage reporting (Scaleway, Mistral's new browser sign-in), using omp's `get_logout_accounts` listing.
- `eff093f`, `9c713fc`, `f10f31b`: GitHub run watches distinguish pending jobs and label job states; classic command results skip omp 18.16's execution status lines; plugin failures drop leading `[!!]` and `[-]` markers.
- `138db33`: omp 18.16 puts a prompt it rejects before a turn (no model, no credential, or `Nothing to resume`) back into its editor. The app now keeps that message as one queue row with omp's error until you retry or remove it, never appends it to the next message, and shuts omp down through the SDK instead of typing `/exit` into a restored draft. Every classic send now checks omp's editor in one native-extension job first (measured median about 260 ms from send to omp receiving the prompt, down from about 770 ms before the job was merged); the owner chose to keep this check and to block sending when the extension bridge is unavailable. Any change to the native bridge's 250 ms poll affects this cost.
