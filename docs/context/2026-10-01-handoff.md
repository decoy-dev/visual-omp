# Session handoff, 2026-10-01

This handoff records visual-omp's state after publishing 0.2.1 and 0.3.0 and obtaining the owner's approval to release 0.3.1. Publication of 0.3.1 is pending. It replaces [2026-09-30-handoff.md](2026-09-30-handoff.md) as the latest handoff.

## Releases

- **0.2.1** (tag `v0.2.1` at `cc5f4f0`) fixes the macOS "visual-omp is damaged and can't be opened" error. 0.2.0 carried only Electron's linker signature, which fails the check macOS runs on a quarantined copy, so the bundle is now ad-hoc signed as a whole (`mac.identity: "-"`, `hardenedRuntime: false`). Both published disk images passed `codesign --verify --deep --strict`, and a quarantined copy opened to the "Not Opened" dialog that leads to **Open Anyway**. The app is still not notarized.
- **0.3.0** (tag `v0.3.0` at `754211e`) keeps a live chat's earlier messages on screen during a reply, keeps the transcript visible while a new collab room loads, paces streamed text through a playout buffer, moves stopping to one button in the composer with fit-based compaction of its bottom row, adds the **Outputs** tab, and collapses the session header's buttons to icons when the chat is narrow.
- **0.3.1** is approved for release. The owner tested `0396a47` in a development build, but its two `scanMadeFiles` tests compare native paths with `/` and fail on Windows CI. The proposed release target is the commit containing the test-helper correction. Its changes from `0396a47` are limited to `src/main/services/panes.test.ts` and this handoff. Before tagging it, the owner must test and approve that commit or explicitly authorize an exception for these test and documentation changes. 0.3.1 finds files that commands and scripts write, previews PDFs, splits Outputs into made, other files and viewed, shows the version in the title bar, turns file and folder names in finished replies into chips and rows that open in the **Files** tab, lets the Files tab open any path and folder with a hideable tree, and adds **Expand preview** for wide images and PDFs. The version commit `60716d8` preceded the last two feature commits, which extended the 0.3.1 CHANGELOG section, so the release does not use `60716d8`.

The owner's installed copy is `/Applications/visual-omp.app` from the Homebrew cask (0.3.0 at the time of writing); `brew update && brew upgrade --cask visual-omp` moves it to the newest release.

## Process the owner set this session

- The owner tests every release first. The release commit is made, a development build of that exact commit is started with `npm run dev` and left open, and the push and tag wait for the owner's go-ahead (AGENTS.md, docs/RELEASING.md). If the commit changes, the owner tests again.
- Work that arrives after a version is chosen goes into that version when the owner says so ("these changes should be part of 0.3.1").

## Decisions

- The owner chose to open PDFs in their default app directly, without a confirmation dialog. The advisor had recommended one because PDFs can contain scripts that a default app such as Acrobat may run.
- Reversible calls taken without an explicit owner decision, each documented in DESIGN.md:
  - When omp's live stream leaves out a parent entry, `activeBranch` uses the saved file's ancestry, and otherwise infers the parent from arrival order. The inference can still pick the wrong branch, for example after a rewind to an unsaved entry with no streamed child.
  - Streaming text trails what omp has sent by an adaptive buffer (about 0.8 s in the measured run).
  - Outputs lists images omp only viewed, below what it made, and the thumbnail grid is a documented exception to the identical-card-grid rule.
  - At the narrowest composer widths the context ring leaves the bottom row; the status bar still shows usage.
  - File discovery from commands is best effort: it can miss files a command never names and can include unrelated files changed at the same time.
- Still undecided from the previous handoff: checking GitHub on every launch (the app reuses a saved update check for up to six hours), and the GitHub repo description, which still contains an em dash (proposed: "visual-omp provides a desktop interface for the omp (oh-my-pi) coding agent, with chats, projects, plan review and subagents.").

## Technical notes for the next session

- **omp's live stream omits entries.** omp 18.4.9's collab host replicates only `message`, `custom_message`, `compaction`, `branch_summary`, `model_change` and `thinking_level_change` entries, but omp writes `custom` entries (`tool_execution_start` between every tool call and its result) and `title_change` entries into the session tree. Live entries therefore name parents the app never receives; `activeBranch` in `state/history.ts` bridges them, and `liveEntries` and `carryover` in `state/session.ts` keep the transcript on screen across room changes.
- **Streaming cadence.** A measured run of omp 18.4.9 with claude-opus-5-5 (`omp -p --mode json`) delivered text in bursts of about 140 characters every 630 ms. The playout buffer in `chat/transcript/pace.ts` is tuned against that pattern.
- **IPC channel names** must match the preload allowlist `/^[a-z]+:[a-zA-Z:.-]+$/` in `src/preload/index.ts`; a name with a capital letter before the colon (for example `fileRefs:resolve`) is rejected at runtime with "blocked channel". The file-link resolver is `fs:resolveRefs`.
- **PDFs in Electron 44.** A `blob:` PDF in an iframe renders through Chromium's built-in viewer under the app's sandbox and context isolation, so the CSP `frame-src` allows `blob:`. The shared `PdfFrame` appends `#navpanes=0&view=FitH`. Thumbnails come from `nativeImage.createThumbnailFromPath` (QuickLook on macOS); Linux has no implementation and shows a glyph.
- **Testing.** The renderer has no DOM test environment, so component behavior is checked in headless Chrome harnesses on their own Vite port and `cacheDir`, and pure logic gets Vitest tests. All 459 tests passed locally on macOS at `0396a47`; Windows CI later exposed the two path-separator assertions described below.
- **CI.** The Windows job once failed the 10 s `beforeEach` in `src/main/features/memory/mnemopi.test.ts` (on the 0.2.1 release commit) and passed on the next run; treat a repeat as worth investigating instead of re-running. It also failed on `79da96a` because two `scanMadeFiles` tests compared the scan's native Windows paths with `/`; the test helper now converts separators. Main-process tests that compare paths must allow for `\` on Windows.

## Open items

- In a narrow chat the composer truncates the model button ("Choose mod…") while the thinking button keeps its full label; the fit-based tiers should compact other controls before truncating the model name. The owner has been offered this fix.
- The title bar grid, the composer tiers and the new file previews were checked only on macOS. Windows behavior has not been seen on a real machine.
- File-link results are cached per reply and checked again when the reply's text or lookup bases change. A cached link can become stale if the file moves or is deleted. Names become links after the reply finishes streaming.
- Gaps carried over from the previous handoff: the transcript view menu shows a "⌘O" hint although ⌘O opens a folder; the Windows title bar overlay is 44 px tall while the renderer's bar is 40 px; shortcut hints show Mac glyphs on every platform; "Agent working" in `ui/Chip.tsx` and the "Context usage" label in `ui/ContextRing.tsx` are hard-coded English; a newly created folder sorts to the bottom of the sidebar until its first chat is saved.
