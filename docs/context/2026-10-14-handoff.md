## Technical notes

- **Saved chats:** `SessionController.ensureLive()` resolves once the pty is spawned, before omp creates its `OMP_TUI_DEBUG` socket, so `host:screen` failed with `connect ENOENT …/tui.sock`. `readyEditor` now awaits `SessionController.whenLive()` (omp running and its collab mirror live), which replaced the private `#whenLive` and the duplicate helper in `chat/composer/send.ts`. It also rejects when omp exited before the call subscribed. Every screen-driven session tool waits for this, including the thinking picker.
- **Model confirmation:** `switchModel` now waits up to 8 s for `guest.state.model` to match the target provider and id (omp broadcasts collab state on `model_changed`). The previous screen diff failed in two ways that were reproduced: omp's `showStatus` rewrites its previous status line in place, so `newOutput` fell back to older transcript lines and treated any line with "error" as a failure; and during a turn omp prints the status above its working indicator, so the diff anchored on that line, saw nothing and returned success after 8 s regardless of the outcome. omp's own rejections ("Unknown model", "No API key for …") appear only on screen, where a reply can print the same text, so an unconfirmed switch ends with a warning: the standard one points to the terminal sheet, and a chat longer than the target's context window gets one about possible compaction. The advisor accepted that trade-off. In the dev build, confirmation took 130 to 230 ms in a live chat and about 710 ms in a saved chat, including omp's start.
- **Homebrew ask mode:** since Homebrew 6.0 (`bc44e3d019` in Homebrew's history), `brew upgrade` with a TTY asks for confirmation when its plan names a package the command did not. The plan names the cask `decoy-dev/tap/visual-omp`, so the in-app terminal always stopped. `brewUpgradeCommand` sets `HOMEBREW_NO_ASK=1`. A throwaway tap cask confirmed both behaviors with Homebrew 7.0.9 in a pseudo-terminal, and the tap, cache file, trust entry and developer mode change were removed afterwards. Copies older than 0.4.2 build the old command, so their update to 0.4.2 still asks once; the release notes say so.
- **Driving the dev build:** a module imported from the console with a bare path (`/src/state/app.ts`) is a second instance once Vite has hot-updated the module, because the page imports it with a `?t=` query. Import the URL from `performance.getEntriesByType("resource")` instead. Using a stale instance sent a test prompt to the owner's "JIRA: Swap ServiceNow logo for Jira" chat in the dev profile; its session file was cut back to its original 118 lines and timestamp, and the owner was told. A closing popover can stay in the DOM with `data-state="closed"` while the dev window is in the background, so check `data-state` when deciding whether a picker is open.
