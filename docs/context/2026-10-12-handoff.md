# Session handoff, 2026-10-12

This handoff records visual-omp's state after the session that fixed the macOS "damaged" error for Homebrew installs and published 0.4.0. It replaces [2026-10-01-handoff.md](2026-10-01-handoff.md) as the latest handoff.

## Releases

- **0.4.0** (tag `v0.4.0` at `f8dc0ab`) adds plan usage in the status bar, background alerts, click-to-zoom image previews and SVG outputs, and ships the Homebrew cask that removes quarantine. The owner tried a development build of `f8dc0ab` and asked for the release. CI passed on macOS and Windows for `f8dc0ab` before the tag was pushed. Both published disk images passed `codesign --verify --deep --strict` (ad-hoc, `ltd.decoy.visualomp`, version 0.4.0), their SHA-256 checksums match the cask, and the workflow updated the cask in `76a045a`.
- The cask change (`558ed35`, `d01f5ca`) was pushed to `main` before 0.4.0, so Homebrew served it with 0.3.1. The owner's copy at `/Applications/visual-omp.app` upgraded to 0.3.1 through Homebrew and opened without a quarantine attribute.

## Decisions

- **Homebrew quarantine:** the owner chose to have the cask remove the quarantine attribute (`postflight_steps` running `xattr -dr com.apple.quarantine`) instead of paying for Apple Developer ID signing and notarization. `docs/SPEC.md` records this. Disk images downloaded from a release still need **Open Anyway**. The cask uses `postflight_steps` because Homebrew 7.0.7 deprecates `postflight` blocks, so it requires Homebrew 6.0.16 or later.
- **macOS alerts:** the owner chose a Dock badge and one bounce per newly unseen chat, without a Script Editor banner workaround. macOS denied native banners to the tested ad-hoc signed build. The owner declined Developer ID signing for now.
- **Plan usage window:** each provider shows its 5-hour window, then its 7-day window, then its monthly window, falling back to its most-used window. A window reported as exhausted takes priority; with pooled accounts every reporting account must report it exhausted.
- **Window names:** windows of one provider that share a name are not merged. Kimi's "Weekly limit" and `limit_7d` are separate meters (one omp report had them at 6% and 0%), so the tooltip shows "7d Weekly limit" and "7d".
- **Folding:** when the status bar runs out of room, the plan item drops window names first, then folds other providers into "+N", then drops provider names, then percents.

## Technical notes

- **Why 0.3.0 said "damaged":** the installed bundle was correctly ad-hoc signed and passed `codesign --verify --deep --strict`. A `ditto` copy in `/tmp` got a fresh Gatekeeper scan and the normal "Not Opened" prompt (`syspolicyd` "Prompt shown (6, 0)"), while `/Applications/visual-omp.app` reused a stored verdict without a scan and got the damaged prompt ("Prompt shown (1, 0)"). Where that stored verdict came from could not be recovered: the unified log kept no entries from the 0.3.0 install on Oct 1, and `/var/db/SystemPolicyConfiguration/ExecPolicy` is root-only.
- **macOS notifications:** `usernoted` delivered the installed app's notifications "as none" with `authorizationStatus: Denied`, and an ad-hoc signed Electron probe received the `failed` event "Notifications are not allowed for this application". `app.dock.setBadge` works for the same probe. Main now absorbs the failure and still requests the notification.
- **Alerts architecture:** the renderer counts unseen chats (`src/renderer/src/features/onboarding/attention.ts`) and sends `app:attention`; `src/main/attention.ts` validates every request, shows the Dock badge or the Windows taskbar flash and overlay, and clears them itself on focus, reload, renderer loss and window close. Alerts need the window open; closing the macOS window stops them.
- **SVG:** main adds a missing `xmlns` to the copy it sends (`svgRootAttributes` scans the prolog forward once; an earlier regex was exponential), folder scans include `.svg`, and reply rows draw SVG thumbnails in the renderer. SVG is never handed to the operating system.
- **Driving the dev build:** `npx electron-vite dev --remoteDebuggingPort 9333` allows CDP control of the renderer without moving the owner's pointer. A subagent harness once connected to the same port and navigated the dev window, so harnesses must use other ports (9444 was used afterwards). Restart with plain `npm run dev` before leaving a build for the owner.
- **Testing:** 554 Vitest tests pass on macOS, and CI passed them on Windows, including `src/main/attention.test.ts`, which switches `process.platform` per test with Electron mocked.

## Open items

- Alerts with the macOS window closed would need chat-event detection moved into the main process. This is an owner decision.
- The owner declined Developer ID signing and notarization for now. These would remove the documented **Open Anyway** step for disk-image installs. Whether a Developer ID signed build receives native banners remains unverified.
- Kimi's window names come from parsing omp's raw ids (`limit_7d`); a provider that changes its naming may need another look.
- Carried over from the previous handoff: the composer truncates the model button in a narrow chat before compacting other controls; the title bar grid, composer tiers and file previews were checked only on macOS; cached file links can become stale; the transcript view menu shows a "⌘O" hint although ⌘O opens a folder; the Windows title bar overlay is 44 px tall while the renderer's bar is 40 px; shortcut hints show Mac glyphs on every platform; "Agent working" in `src/renderer/src/ui/Chip.tsx` and the "Context usage" label in `src/renderer/src/ui/ContextRing.tsx` are hard-coded English; a newly created folder sorts to the bottom of the sidebar until its first chat is saved.

The proposed description is "visual-omp provides a desktop interface for the omp (oh-my-pi) coding agent, with chats, projects, plan review and subagents."
